MedDoc RAG

Citation-grounded question answering over 8 WHO, CDC and NIH guidelines, 1,077 pages in total.

Livemedicrag.streamlit.appPreview
Problem
An answer pulled from a long guideline is only useful if each claim can be traced to its source, and if the system refuses questions the documents do not cover.
Flow
  1. 8 PDFs
  2. Section-aware chunks
  3. bge-small + FAISS
  4. Cross-encoder rerank
  5. Grounded LLM
  6. Citation check
  7. FastAPI
Built
PyMuPDF parsing, section-aware chunking, bge-small embeddings with FAISS and cross-encoder reranking, feeding a grounded LLM answer that is checked against its citations. Served with FastAPI and Streamlit, packaged with Docker, with pytest and GitHub Actions CI. Built on pretrained models.
Safety
A relevance gate that refuses out-of-scope questions, citation validation, a prompt-injection classifier, output validation, and red-teaming.
Tested
3 chunking strategies against 5 retrievers, including BM25 with Reciprocal Rank Fusion, on a 48-question golden set I wrote and checked. Scored with Hit@k, MRR and paired bootstrap confidence intervals. Section-aware chunking won. Adding BM25 to dense search showed no significant gain, so I shipped the simpler pipeline.
Result
95.8% Hit@5 and 0.741 MRR on that 48-question set. 44 of 48 answers correct in my manual audit. 11 of 11 out-of-scope questions refused. 0 citations to sources the model was not given.
Stack
  • Python
  • PyMuPDF
  • FAISS
  • FastAPI
  • Streamlit
  • Docker
  • pytest
  • GitHub Actions

One question is 2.1 points on a 48-question set. The models are pretrained. Educational project, not medical advice.

Neuro

A controlled comparison of 7 classical ML and 2 deep learning models that classify healthy and mood-disorder subjects from EEG features, with SHAP explanations and a FastAPI service.

Liveneuro-rose.vercel.appPreview
Problem
Depression screening still leans on questionnaires and interviews. EEG is an objective signal but noisy and high-dimensional, and published comparisons of classical ML and deep learning often use different preprocessing, so it is unclear which actually works on a small EEG dataset.
Data
The public BRMH EEG Psychiatric Disorders dataset, filtered to a binary task: healthy controls vs mood disorder (n = 361). Stratified 80/20 split, leaving 73 held-out test subjects.
Flow
  1. EEG features
  2. FAA, θ/α, β/α, δ asymmetry
  3. StandardScaler
  4. PCA, 95% variance
  5. SMOTE, train only
  6. 7 ML + 2 DL models
  7. 5-fold CV + test
  8. SHAP
  9. FastAPI
Built
Four clinically motivated biomarkers: frontal alpha asymmetry, theta/alpha ratio, beta/alpha ratio and delta asymmetry. Mean imputation, StandardScaler, PCA keeping 95% of the variance, SelectKBest, and SMOTE on the training data only. Models: logistic regression, SVM (RBF), random forest, XGBoost, LightGBM, MLP and a voting ensemble, plus a fully connected ANN and a CNN+LSTM. SHAP on XGBoost, and a FastAPI service for inference.
Tested
Every model got the same preprocessing and the same split: stratified 5-fold cross-validation, then the 73 held-out subjects, against a majority-class baseline of 73.7%.
Result
XGBoost and the voting ensemble tied at 80.82% test accuracy (cross-validation 77.8% ± 2.7 and 79.8% ± 5.7). The deep learning models reached 68.49%, below the baseline: on a small, structured dataset, classical ML won. SHAP ranked frontal alpha and theta features highest, in line with the clinical literature. A later leakage-free check with 10 × 5-fold cross-validation was more modest: accuracy 73.1% ± 3.8 against the 73.7% baseline, ROC-AUC 0.72, so the signal is real but small.
App
The model runs inside the Neuro web app (React, Three.js): Web Bluetooth EEG capture from Muse and OpenBCI headsets with in-browser FFT band power, an EEG-aware therapist chat through a serverless LLM function, and this XGBoost model running in the browser, with plain-language explanations.
Try it
The app's Prediction Model screen runs on any recording: pick one of the 73 held-out people or upload an EEG file (CSV in the dataset's format, read only in the browser). The full pipeline (biomarkers, scaling, PCA projection, 100 trees) runs client-side and matches the Python model on every held-out subject. Each answer comes with plain-language reasons, grouped by brainwave and head region (for example, how in sync calm alpha waves are between the front and the back of the head), and sliders turn each brainwave's strength or synchrony up or down to show what the model responds to.

Healix

An AI-assisted healthcare dashboard in the browser: sign in, consult an AI doctor, analyse a medical report and track medication and treatment, on a 3D interface.

Livedevops-zeta-nine.vercel.appPreview
Problem
Personal health information ends up scattered across chats, reports and reminders. Bringing it into one app means handling sign-in and private data properly, and an AI feature in a browser app needs an API key that must never reach the browser.
Flow
  1. React UI
  2. Firebase Auth
  3. Zustand
  4. React Three Fiber, 5 GLB models
  1. AI request
  2. Vercel serverless function
  3. OpenRouter
Features
Dr. AI consultation chat with conversation export, a report analyser that reads an uploaded report and summarises it, a medication manager with adherence tracking, a treatment tracker, a health overview and an emergency screen.
Built
React 18, Vite and Tailwind CSS, with Three.js and React Three Fiber for the 3D dashboard, Zustand for state and React Router. The dashboard is lazy-loaded, so the landing page never downloads Three.js. LLM chat and report summaries go through OpenRouter via Vercel serverless functions, with a fallback AI when the service is down.
Data
Firebase Authentication (email and password) protects the dashboard. Chat history, report analyses and health data live in Firebase Realtime Database under each user's ID, and security rules let users read and write only their own records.
DevOps
GitHub Actions CI lints, builds and pushes a Docker image to GitHub Container Registry. Docker Compose for local and production runs, Kubernetes manifests and Prometheus and Grafana monitoring configuration in the repo, and a separate Jenkins pipeline on AWS EC2.
Result
A deployed demo anyone can open.

HealthMonitor

Real-time vital-sign monitoring from an ESP32 wearable to a web dashboard, with an alert engine that combines the NEWS2 early-warning score with each patient's own baseline.

Livefinal-iot-delta.vercel.appPreview
Problem
Fixed alarm thresholds miss a patient who is slowly deteriorating while still "normal" on paper, and they fire on every glitchy sensor reading.
Flow
  1. MAX30102 + DS18B20
  2. ESP32
  3. Wi-Fi
  4. Express API
  5. Firebase RTDB
  6. Alert worker
  7. Dashboard
Hardware
ESP32 firmware in Embedded C/C++ reads a MAX30102 (heart rate, SpO2) and a DS18B20 (temperature) and sends live vitals as JSON over Wi-Fi to the Express API, along with device heartbeats; the API stores them in Firebase Realtime Database.
On device
The ESP32 also alerts locally, sounding a buzzer and flashing an LED when readings go out of range, so a warning still reaches the bedside without internet. The MAX30102 is read over I2C and the DS18B20 over 1-Wire.
Alerts
Four layers. NEWS2 scoring is a fixed safety floor: a total of 7 or more is critical; 5 to 6, or any single parameter scoring 3, is a warning. Adaptive per-patient baselines keep slow and fast exponentially weighted averages and alert when the fast one moves 3.5 standard deviations from the patient's own baseline, after a 30-minute warm-up, learning ten times slower while the patient looks abnormal. Signal-quality checks catch lost or frozen sensors. A condition must persist (10 seconds if critical, 30 otherwise) before it alerts; worsening escalates the open alert instead of duplicating it, and alerts auto-resolve after 10 minutes clear.
Feedback
Clinicians mark each alert as useful or a false alarm. A false alarm raises that patient's threshold for that vital by 1.15× (up to 1.8×), a useful alert lowers it by 0.95× (down to 0.85×). NEWS2 thresholds never change, and every alert carries a plain-language explanation of the scores behind it.
Notify
Warning and critical alerts are emailed (SMTP) and texted (Twilio) to the care team when they are created or escalated, and every send is recorded on the alert as sent, skipped or failed. Covered by 7 more Jest tests.
Platform
Node.js/Express REST API on Vercel serverless, plus an always-on alert worker. JWT sessions, email and password plus Google and GitHub sign-in through Firebase Auth, a read-only demo account, rate-limited login, Helmet headers and optional device API keys. A live Chart.js dashboard with 7, 30 and 90-day trends, and Dr. AI, a 3D assistant that answers questions about the current vitals through OpenRouter with a built-in fallback.
Tested
40 Jest test cases on the alert engine: 22 tests plus an 18-row table covering the NEWS2 scoring bands.
Result
Dashboard deployed on Vercel, with a read-only demo tour.
Paper
Co-authored a research paper on the system, IoT-Based Intelligent Health Monitoring and Alert System (SRM IST, 2026).
